# Third-party review items - INTERNAL, never publish

Written by `python3 -I packaging/release-repo/tools/gen_third_party_notices.py` on 2026-11-06 together with THIRD_PARTY_NOTICES.md. The release job publishes only LICENSE.md and THIRD_PARTY_NOTICES.md; keep this file out of the public repo.

- **Video codecs / patents.** Lumora ships no H.264 implementation of its own and downloads nothing at run time. H.264 is used only through the operating system's codec (Android MediaCodec, Apple VideoToolbox, Windows Media Foundation, VA-API on Linux), whose patent licensing is the OS vendor's. The always-available codec is libvpx VP8/VP9 (BSD-3-Clause + Google's royalty-free patent grant). Release builds contain no OpenH264. A source-built OpenH264 exists only behind the dev/test cargo feature `openh264-source`; CI fails if it appears in a release dependency graph. Confirm this position with counsel before relying on it where H.264 patents are in force.
- **Bundled - BIP-39 English word list (recovery phrase):** The BIP-39 document carries no explicit license header in the bitcoin/bips repository (a list of common English words is probably not copyrightable). Owner/lawyer to confirm; credit the source anyway.
- **Bundled - Demo/mock assets (photos assets/mock/*.jpg, sample files assets/mock/files/*):** These files are listed in pubspec.yaml and therefore ship inside every build. Their origin/license is not recorded in the repo. Either confirm they were created by the owner (or are licensed for redistribution), or drop them from release builds.
- **Bundled - PDFium (prebuilt by pdfium-binaries / pdfium-xcframework, downloaded by pdfium_flutter at build time):** The PDFium binary also contains third-party libraries (for example FreeType, libjpeg-turbo, libpng, zlib, Little CMS, OpenJPEG) under their own licenses. The pdfium-binaries archive ships a LICENSE file / licenses folder with all of them: copy that text into the release (e.g. append it here) - this script cannot see it because the archive is only downloaded during `flutter build`. FreeType's FTL requires a credit line in the documentation. pdfrx's pdfium.wasm (web only) is removed in CI by `dart run pdfrx:remove_wasm_modules`.
- **Bundled - Google Play services Location (com.google.android.gms:play-services-location, via geolocator_android):** Proprietary Google component inside the APK (not open source). Allowed for apps, but its terms are Google's, and it is unavailable on de-Googled devices. Its own notices can be generated with the oss-licenses Gradle plugin.
- **Bundled - Microsoft Visual C++ runtime DLLs (msvcp140.dll, vcruntime140.dll, vcruntime140_1.dll):** App-local deployment is allowed only for holders of a Visual Studio license that grants distributable-code rights, and Microsoft asks that the files be taken from the Visual Studio redist folder (VC\Redist\MSVC\<ver>\x64\Microsoft.VC143.CRT), not copied from System32 as packaging/windows/README.md currently does.
- **Bundled - Inno Setup (installer engine / setup stub inside the Windows installer .exe):** The setup stub compiled into the installer is Inno Setup code. Check the CURRENT Inno Setup license (https://jrsoftware.org/files/is/license.txt): recent releases changed the terms for commercial use - confirm a freeware release qualifies or buy a commercial license; keep its copyright notice in the installer.
- **Bundled - OpenStreetMap map tiles (location messages):** The OSM Foundation tile usage policy forbids heavy use without permission and requires a valid User-Agent; consider a commercial tile provider for a public release. Also mentioned in the EULA privacy section.
